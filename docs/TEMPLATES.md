# Шаблон комплекта чертежей

Шаблон — это JSON-файл в папке `templates/` (или в папке из `REVIT_MCP_TEMPLATES_DIR`),
описывающий, какие листы создать, что на них разместить и куда выгрузить результат.
Имя файла без расширения — имя шаблона.

Готовые шаблоны:

- `obmer-ar` — обмерный комплект: план на каждый уровень, два разреза, 3D-вид, выгрузка в PDF;
- `plany-po-etazham` — по одному листу с планом на этаж, без выгрузки.

## Структура

```json
{
  "description": "Обмерный комплект АР",
  "titleblock": "A1 метрический",
  "numbering": { "prefix": "АР-", "start": 1, "digits": 2 },
  "sheet_parameters": { "Дата": "{date}", "Стадия": "Обмерные работы" },
  "sheets": [ { "...": "блоки листов" } ],
  "export": { "format": "pdf", "combine": true, "folder": "C:\\Revit\\Выгрузка" }
}
```

| Поле | Назначение |
| --- | --- |
| `titleblock` | Имя типа основной надписи: `«A1 метрический»` или `«Рамка: A1 метрический»`. Без него берётся первая рамка проекта |
| `numbering` | Автонумерация листов: префикс, начальный номер, число разрядов |
| `sheet_parameters` | Параметры штампа, общие для всех листов |
| `sheets` | Блоки листов; порядок сохраняется, нумерация сквозная |
| `export` | Выгрузка после сборки. `format`: `pdf` или `dwg` |

## Блок листов

```json
{
  "for_each_level": true,
  "levels": ["Этаж 1", "Этаж 2"],
  "number": "{auto_number}",
  "name": "План {level_name}",
  "parameters": { "Наименование": "План {level_name}" },
  "views": []
}
```

`for_each_level: true` превращает блок в лист на каждый уровень модели; `levels` ограничивает
набор уровней по именам. Без `for_each_level` блок даёт ровно один лист.

## Виды

| `kind` | Что создаётся | Обязательные поля |
| --- | --- | --- |
| `plan` | План этажа | уровень (из `for_each_level` или `level_id`) |
| `ceiling_plan` | Потолочный план | то же |
| `section` | Разрез | `origin`, `direction` |
| `elevation` | Фасад | `origin`, `direction` |
| `3d` | Трёхмерный вид | — |
| `existing` | Существующий вид проекта | `view_name` |

Общие необязательные поля: `name`, `scale`, `view_template` (имя шаблона вида),
`detail_level` (`Coarse`, `Medium`, `Fine`), `position`.

Для разрезов и фасадов: `direction` — направление взгляда, `width_mm`, `height_mm`, `depth_mm`
задают секущий контейнер.

```json
{
  "kind": "section",
  "name": "Разрез 1-1",
  "scale": 50,
  "origin": { "x": 0, "y": 0, "z": 0 },
  "direction": { "x": 0, "y": 1, "z": 0 },
  "width_mm": 20000,
  "height_mm": 8000,
  "depth_mm": 15000,
  "position": { "x_mm": 250, "y_mm": 400 }
}
```

## Раскладка видов на листе

Если у вида задан `position`, он ставится в эту точку (начало координат — левый нижний угол
листа, миллиметры). Если координат нет, виды раскладываются сеткой по размеру рамки: слева
направо, сверху вниз. Размер берётся из основной надписи листа; если рамки нет — принимается A1.

## Подстановки

В `name`, `number`, значениях `parameters`, а также в `name`/`view_name`/`view_template` видов
работают подстановки:

| Ключ | Значение |
| --- | --- |
| `{auto_number}` | Номер по правилам `numbering` |
| `{index}` | Порядковый номер листа числом |
| `{level_name}` | Имя уровня (в блоках `for_each_level`) |
| `{level_elevation_mm}` | Отметка уровня |
| `{project_name}` | Название открытого проекта |
| `{date}` | Текущая дата, ГГГГ-ММ-ДД |

Неизвестные подстановки остаются в тексте как есть — шаблон из-за них не ломается.

## Проверка перед выпуском

`revit_preview_sheet_template` показывает список листов, которые будут созданы для текущего
проекта, ничего не меняя. Ошибки в структуре шаблона (неизвестный `kind`, разрез без `origin`,
нецелый масштаб) выводятся с указанием пути к проблемному полю.

Если отдельный вид или лист создать не удалось, выпуск не прерывается: проблема попадает в
поле `problems` соответствующего листа в итоговом отчёте.
