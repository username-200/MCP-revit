# Наработки под перенос

Здесь лежит то, что пережило удаление собственного HTTP-моста: алгоритмы, не
завязанные на транспорт. Это **не рабочий код**, а исходный материал для переноса
на команды плагина [LuDattilo/revit-mcp-server](https://github.com/LuDattilo/revit-mcp-server).

Причина сохранения: в том плагине нет инструментов для облаков точек, а
обмерная задача без них не решается.

---

## plane-detection/ — поиск плоскостей в облаке (C#)

| Файл | Что делает |
| --- | --- |
| `PlaneDetector.cs` | RANSAC: ищет плоскости в наборе точек, уточняет их методом наименьших квадратов, строит след стены в плане |
| `Jacobi.cs` | Собственные векторы ковариационной матрицы — уточнение нормали по облаку инлаеров |
| `DetectedPlane.cs` | Плоскость и её сериализация: тип (горизонтальная / вертикальная / наклонная), отметки, азимут следа |
| `UnitConv.cs` | Футы ↔ миллиметры: внутри Revit футы, наружу отдаются миллиметры |
| `Dto.cs` | Точка и вектор в виде словаря — обрезано до двух методов, нужных детектору |

Код написан под Revit API (`Autodesk.Revit.DB.XYZ`) и компилировался в составе
прежнего аддина. Пространство имён осталось `McpRevit.*` — при переносе его
придётся сменить.

**Как переносить.** Плагин LuDattilo даёт `send_code_to_revit`: произвольный C#
выполняется внутри Revit, доступны `document` и `parameters`, автоматически
подключены `System`, `System.Linq`, `Autodesk.Revit.DB/UI`. Точки из облака берутся
через `PointCloudInstance.GetPoints(filter, density, maxPoints)`; дальше применим
`PlaneDetector` как есть.

Ограничение подхода: код передаётся строкой на каждый вызов, поэтому длинные
алгоритмы неудобно отлаживать. Разумнее собрать эти файлы в отдельную сборку и
подгружать её, либо добавить свою команду в `commandset/` того проекта.

## sheet-templates/ — движок шаблонов чертежей (Python)

| Файл | Что делает |
| --- | --- |
| `templates.py` | Разбор JSON-шаблона, разворачивание по уровням проекта, подстановки в штамп, автораскладка видов на листе |
| `test_templates.py`, `test_layout.py` | 16 тестов на разбор шаблонов и раскладку |

Модуль самодостаточен: зависит только от стандартной библиотеки и читает шаблоны
из `../../templates/`. Формат шаблона описан в [../docs/TEMPLATES.md](../docs/TEMPLATES.md).

Запуск тестов:

```bash
python -m pytest porting/sheet-templates -q
```

**Как переносить.** `templates.expand()` возвращает готовый план комплекта: номера
листов, имена, привязку к уровням, список видов. Дальше нужны команды плагина:
`create_view`, `create_sheet` (или `batch_create_sheets`), `place_viewport`,
`batch_export`. Прежний конвейер вызывал ровно эту последовательность, только
через собственный мост.

## wall-grouping.ps1 — деление стен на периметр и перегородки

Эвристика: следы плоскостей, лежащие у края габаритного прямоугольника плана, —
наружные стены, остальные — перегородки. Дальше каждая группа строилась своим
типоразмером (например, железобетон 150 мм и керамзитоблок 90 мм).

Скрипт обращался к командам удалённого моста (`pointcloud.detect_planes`,
`walls.from_planes`), которых больше нет, поэтому как есть он не запустится.
Ценность — в самой классификации: расчёт габаритов, отбор по положению середины
следа, отчёт перед записью в модель.

Эвристика работает на прямоугольной планировке. При сложной форме плана (эркер,
П-образный контур) часть наружных стен попадёт в перегородки — поэтому запись
включалась только явным ключом, а по умолчанию печатался разбор.
